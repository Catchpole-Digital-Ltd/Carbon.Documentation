# Control Panel Architecture

The Control Panel is a WebRCon-based administration tool that provides remote server management capabilities for Rust servers running Carbon. It supports two communication protocols: the legacy JSON-based RCON and the modern binary-based Bridge protocol.

## Overview

The control panel is built with Vue 3 and provides:
- Real-time console log streaming
- Chat management with customizable identity
- Player list with inventory editing
- Entity search and manipulation
- Plugin management (load/unload/reload)
- Permission group management
- Performance profiler integration
- Live server map with entity tracking

## Communication Protocols

### Protocol Selection

The panel supports two protocols, selected via the "Bridge" toggle when configuring a server:

| Feature | Legacy RCON (JSON) | Bridge Protocol (Binary) |
|---------|-------------------|-------------------------|
| Format | JSON strings | Binary serialization |
| Efficiency | Lower | Higher |
| Features | Basic console/chat | Full feature set |
| Authentication | Password in URL | Password in URL |

### Connection Flow

```
┌─────────────────┐     WebSocket      ┌──────────────────┐
│  Control Panel  │ ←────────────────→ │   Rust Server    │
│    (Browser)    │   ws(s)://host/pw  │ (Carbon Bridge)  │
└─────────────────┘                    └──────────────────┘
```

Connection is established via WebSocket:
```typescript
this.Socket = new WebSocket(
  (this.Secure ? 'wss' : 'ws') + '://' + this.Address + '/' + this.Password
)
```

For Bridge protocol, binary mode is enabled:
```typescript
if (this.Bridge) {
  this.Socket.binaryType = 'arraybuffer'
}
```

## RPC System

The RPC (Remote Procedure Call) system enables structured communication between the panel and server.

### RPC ID Generation

RPC identifiers are generated by hashing the RPC name with MD5:

```typescript
getId(id: string): number {
  const idPrefix = this.Bridge ? 'RPC' : 'CMD'
  return Number.parseInt(md5(`${idPrefix}_${id}`))
}
```

### Registering RPC Handlers

Handlers are registered during connection setup:

```typescript
registerRpcs() {
  this.setRpc('ServerInfo', (read) => {
    this.ServerInfo = {
      Hostname: read.string(),
      MaxPlayers: read.int32(),
      Players: read.int32(),
      Queued: read.int32(),
      Joining: read.int32(),
      // ... additional fields
    }
  })

  this.setRpc('Players', (read) => {
    this.PlayerInfo = []
    const playerCount = read.int32()
    for (let i = 0; i < playerCount; i++) {
      this.PlayerInfo.push(this.readPlayer(read))
    }
  })

  // Additional handlers: ConsoleTail, ChatTail, Plugins, etc.
}
```

### Sending RPC Calls

RPC calls are made using `sendCall()`:

```typescript
sendCall(id: string, ...args: unknown[]) {
  if (this.Bridge) {
    const write = new BinaryWriter()
    write.int32(0)  // Message type: RPC
    write.uint32(this.getId(id))

    // Serialize arguments by type
    for (const value of args) {
      switch (typeof value) {
        case 'bigint': write.uint64(value); break
        case 'number': write.int32(value); break
        case 'string': write.string(value); break
        case 'boolean': write.bool(value); break
      }
    }
    this.Socket?.send(write.toArrayBuffer())
  } else {
    // Legacy: send as console command
    this.sendCommand(`c.webpanel.cmd ${this.getId(id)} ${args.join(' ')}`, 100)
  }
}
```

### Available RPCs

| RPC Name | Direction | Description |
|----------|-----------|-------------|
| `ServerInfo` | Request/Response | Server hostname, player counts, FPS, memory |
| `CarbonInfo` | Request/Response | Carbon version and build information |
| `Players` | Request/Response | Full player and sleeper list |
| `Plugins` | Request/Response | Installed plugins with metadata |
| `ConsoleTail` | Request/Response | Last N console log entries |
| `ChatTail` | Request/Response | Last N chat messages |
| `ConsoleLog` | Server Push | New console log entry |
| `ChatLog` | Server Push | New chat message |
| `ConsoleInput` | Client Send | Execute console command |
| `ChatInput` | Client Send | Send chat message |
| `AccountPermissions` | Request/Response | Current user's permissions |
| `SearchEntities` | Request/Response | Entity search results |
| `RequestMapEntities` | Request/Response | Map entity positions |
| `LoadMapInfo` | Request/Response | Map metadata and image |

## Message Flow

### Console Commands

```
User Input → sendCommand() → WebSocket
                              ↓
                         Server Executes
                              ↓
              ConsoleLog RPC ← WebSocket
                    ↓
            appendLog() → UI Update
```

```typescript
sendCommand(input: string, id: number = 1) {
  if (this.Bridge) {
    this.sendCall('ConsoleInput', input)
  } else {
    const packet = { Message: input, Identifier: id }
    this.Socket.send(JSON.stringify(packet))
  }
  this.appendLog('> ' + input)
}
```

### Chat Messages

```
User Input → sendMessage() → ChatInput RPC
                                   ↓
                              Server Broadcasts
                                   ↓
                ChatLog RPC ← WebSocket (to all clients)
                      ↓
              appendChat() → UI Update
```

```typescript
sendMessage(input: string) {
  if (this.Bridge) {
    this.sendCall('ChatInput',
      this.ChatUsername,
      input,
      this.ChatColor,
      this.ChatUserId
    )
  } else {
    this.sendCommand(`say ${input}`, 1)
  }
}
```

### Message Reception

```typescript
this.Socket.onmessage = (event) => {
  if (this.Bridge) {
    const read = new BinaryReader(event.data)
    const messageType = read.int32()

    switch (messageType) {
      case 0:  // RPC
        const rpcId = read.uint32()
        if (rpcId in this.RpcCallbacks) {
          this.RpcCallbacks[rpcId](read)
        }
        break
    }
  } else {
    // Legacy JSON parsing
    const resp = JSON.parse(event.data)
    if (this.onIdentifiedCommand(resp.Identifier, resp)) {
      return
    }
    this.appendLog(resp.Message)
  }
}
```

## Permissions System

The control panel implements a permission-based access control system.

### Permission Model

Permissions are fetched on connection via the `AccountPermissions` RPC:

```typescript
this.setRpc('AccountPermissions', (read) => {
  this.RpcPermissions = {}
  const count = read.int32()
  for (let i = 0; i < count; i++) {
    const key = read.string()
    const value = read.bool()
    this.RpcPermissions[key] = value
  }
})
```

### Available Permissions

| Permission | Description |
|------------|-------------|
| `console_view` | View console output |
| `console_input` | Execute console commands |
| `chat_view` | View chat messages |
| `chat_input` | Send chat messages |
| `players_view` | View player list |
| `players_ip` | View player IP addresses |
| `players_inventory` | View/edit player inventories |
| `entities_view` | Search and view entities |
| `entities_edit` | Modify entity properties |
| `permissions_view` | View permission groups |
| `permissions_edit` | Modify permissions |
| `profiler_view` | View profiler data |
| `profiler_load` | Load profile files |
| `profiler_edit` | Start/stop profiling |
| `plugins_view` | View plugin list |
| `plugins_edit` | Load/unload plugins |

### Permission Checking

UI elements are conditionally enabled based on permissions:

```typescript
hasPermission(permission: string): boolean {
  if (permission in this.RpcPermissions) {
    return this.RpcPermissions[permission]
  }
  return true  // Default allow if not restricted
}

// Tab configuration
{
  Name: 'Console',
  IsDisabled: () => !selectedServer.value?.hasPermission('console_view')
},
{
  Name: 'Permissions',
  IsDisabled: () => !selectedServer.value?.Bridge ||
                   !selectedServer.value?.hasPermission('permissions_view')
}
```

### Permission Management

The Permissions tab allows managing group permissions:

```typescript
// Select a permission group

// Toggle a permission for a group

```

## Binary Protocol

### BinaryWriter

Used for serializing outgoing messages:

```typescript
export class BinaryWriter {
  int32(value: number)     // 4-byte signed integer
  uint32(value: number)    // 4-byte unsigned integer
  int64(value: bigint)     // 8-byte signed integer
  uint64(value: bigint)    // 8-byte unsigned integer
  float(value: number)     // 4-byte floating point
  bool(value: boolean)     // 1-byte boolean
  string(value: string)    // Length-prefixed UTF-8 string
  bytes(data: Uint8Array)  // Raw byte array

  toArrayBuffer(): ArrayBuffer
}
```

### BinaryReader

Used for deserializing incoming messages:

```typescript
export class BinaryReader {
  int32(): number          // 4-byte signed integer
  uint32(): number         // 4-byte unsigned integer
  int64(): bigint          // 8-byte signed integer
  uint64(): bigint         // 8-byte unsigned integer
  float(): number          // 4-byte floating point
  bool(): boolean          // 1-byte boolean
  string(): string         // Length-prefixed UTF-8 string
  bytes(length: number): Uint8Array

  // Special string formats
  bstring(): string        // 7-bit encoded length string
  cstring(): string        // Null-terminated string
}
```

### Message Format

Bridge protocol messages follow this structure:

```
┌──────────────┬───────────────┬────────────────────┐
│ Message Type │    RPC ID     │    Payload Data    │
│   (int32)    │   (uint32)    │  (variable length) │
└──────────────┴───────────────┴────────────────────┘
```

## State Management

### Server Class

The `Server` class encapsulates all state for a single server connection:

```typescript
export class Server {
  // Connection state
  Address: string
  Password: string
  Socket: WebSocket | null
  IsConnected: boolean
  Bridge: boolean
  Secure: boolean

  // Server data
  ServerInfo: ServerInfo | null
  PlayerInfo: Player[]
  PluginsInfo: Plugin[]

  // Logs and chat
  Logs: string[]
  Chat: ChatMessage[]
  CommandHistory: string[]

  // Callback registries
  RpcCallbacks: Record<number, Function>
  CommandCallbacks: Record<number, Function>

  // Permissions
  RpcPermissions: Record<string, boolean>
}
```

### Reactive State

Vue refs provide reactive state management:

```typescript
// Global state (ControlPanel.SaveLoad.ts)
export const selectedServer = ref<Server | null>(null)
export const servers = ref<Server[]>([])

// Chat state (ControlPanel.Chat.ts)
export const message = ref('')
export const chatContainer = ref<HTMLDivElement>(null!)

// Console state (ControlPanel.Console.ts)
export const command = ref('')
export const commandIndex = ref(0)
export const consoleContainer = ref<HTMLDivElement>(null!)
```

### Persistence

Configuration is persisted to localStorage:

```typescript
function save() {
  localStorage.setItem('rcon-servers', exportToJson())
}

function exportToJson(): string {
  return JSON.stringify(servers.value, (key, value) => {
    // Exclude runtime state
    if (['Socket', 'IsConnected', 'Logs', 'RpcCallbacks'].includes(key)) {
      return undefined
    }
    return value
  })
}
```

## Connection Lifecycle

### Connecting

```typescript
connect() {
  this.Socket = new WebSocket(
    (this.Secure ? 'wss' : 'ws') + '://' + this.Address + '/' + this.Password
  )

  this.Socket.onopen = () => {
    this.IsConnected = true
    this.registerRpcs()

    // Request initial data
    if (this.Bridge) {
      this.sendCall('ServerInfo')
      this.sendCall('Players')
      this.sendCall('Plugins')
      this.sendCall('ConsoleTail', 200)
      this.sendCall('ChatTail', 200)
      this.sendCall('AccountPermissions')
    }
  }
}
```

### Auto-Refresh

A 10-second interval refreshes server data:

```typescript
setInterval(() => {
  servers.value.forEach((server) => {
    if (!server.IsConnected) return

    if (server.Bridge) {
      server.sendCall('ServerInfo')
      server.sendCall('Players')
    } else {
      server.sendCommand('serverinfo', 2)
      server.sendCommand('playerlist', 6)
    }
  })
}, 10000)
```

### Disconnecting

```typescript
disconnect() {
  this.Socket?.close()
  this.Socket = null
  this.IsConnected = false
  this.clear()  // Reset all data
}
```

## Map Entity Tracking

Real-time entity tracking on the server map:

```typescript
startMapEntityTracking() {
  this.MapEntityUpdateInterval = setInterval(() => {
    const write = new BinaryWriter()
    write.int32(0)
    write.uint32(this.getId('RequestMapEntities'))
    write.int32(this.MapSettings.trackedTypes.length)

    for (const type of this.MapSettings.trackedTypes) {
      write.int32(type)
    }

    this.Socket?.send(write.toArrayBuffer())
  }, 1000)
}
```

Entity types can be filtered to track:
- Players
- Scientists
- Animals
- Vehicles
- Resources
- Buildings
